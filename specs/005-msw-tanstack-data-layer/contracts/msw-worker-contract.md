# MSW Worker Contract

Defines the expected behaviour of the Mock Service Worker integration.

## Activation Contract

| Environment | Worker active | Condition |
|---|---|---|
| `development` (`NODE_ENV=development`) | Yes | Started in `MSWProvider` via dynamic import |
| `production` | No | `NODE_ENV` check prevents import |
| `test` | No | Not in scope; `msw/node` for tests is out of scope |

## Startup Sequence

1. Root layout renders `MSWProvider` (client component)
2. `MSWProvider` mounts; `useEffect` fires
3. If `NODE_ENV === "development"`, dynamically import `@/mocks/browser`
4. `await worker.start({ onUnhandledRequest: "warn" })`
5. Worker is registered; subsequent `fetch` calls from TanStack Query are intercepted

## Handler Coverage

All handlers must be registered before `worker.start()` resolves.

| URL Pattern | Method | Handler file |
|---|---|---|
| `/api/dashboard/review-items` | GET | `handlers/dashboard.ts` |
| `/api/dashboard/chart` | GET | `handlers/dashboard.ts` |
| `/api/dashboard/queue` | GET | `handlers/dashboard.ts` |
| `/api/applications` | GET | `handlers/applications.ts` |

## Unhandled Request Behaviour

- `onUnhandledRequest: "warn"` — logs a console warning for any request not matched by a handler
- No request is blocked; unhandled requests pass through to the network normally

## Service Worker File

- Location: `public/mockServiceWorker.js`
- Generated by: `npx msw init ./public`
- Must be committed to version control
- Must not be modified manually

## Production Guard

The MSW browser package must never enter the production JavaScript bundle. The dynamic import inside the `useEffect` with a `NODE_ENV` guard ensures tree-shakers and bundlers exclude it.
