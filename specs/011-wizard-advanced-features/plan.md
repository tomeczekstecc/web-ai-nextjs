## Implementation Tasks

### Task 1 — Add `calc` demonstration to Krok 2

**File**: `src/app/wizard-demo/page.tsx`

Add a `calc` function to the `krok-2` page entry in `demoPages`. The calc derives `tytul_upr` (uppercase of `tytul`) from the current form state:

```ts
calc: (form) => ({ ...form, tytul_upr: (form.tytul as string ?? '').toUpperCase() })
```

Add a disabled `InputWiz` (or equivalent read-only display) for `tytul_upr` in the `Krok2` component. The field should update automatically when `tytul` changes on any page, because `calc` runs whenever `setValue` is called on Krok 2.

Note: `calc` only runs while the user is on Krok 2 (since it's per-page). To see it in action, navigate to Krok 2 and observe `tytul_upr` auto-populating.

**UI impact**: One new read-only field on Krok 2. Light/dark safe — uses existing input styles.

**Laravel integration note**: `calc`-derived fields appear in the flat form payload on save. Backend should ignore or accept extra fields gracefully.

---

### Task 2 — Add `hide` prop demonstration to Krok 2

**File**: `src/app/wizard-demo/page.tsx`

Add a `typ` select field (using `SelectWiz` or a simple native select via `useWizardField`) to the `Krok2` component. The `tytul_upr` field from Task 1 uses `hide={form.typ === 'prosty'}` to conditionally hide itself when `typ` equals `'prosty'`. This demonstrates the `hide` prop pattern.

Add `SelectWiz` for `typ` with two options: `'prosty'` (simple) and `'złożony'` (complex).

**UI impact**: One new select field on Krok 2. Flex column layout unchanged.

### Task 3 — Add `cancelCallback` to edit-mode wizard

**File**: `src/app/wizard-demo/page.tsx`

Pass `cancelCallback` to the edit-mode `<Wizard>`. The callback shows a sonner toast to make the invocation visible:

```tsx
cancelCallback={() => {
  toast.info('Anulowano — w produkcji nastąpi przekierowanie')
}}
```

**UI impact**: Cancel button in edit mode now has a visible effect. No layout change.

### Task 4 — Add `customButtons` to edit-mode wizard

**File**: `src/app/wizard-demo/page.tsx`

customButtons={() => (

**UI impact**: One additional button on the summary page (last page only).

---

### Task 5 — Improve `acceptButtons` to react to summary errors

**File**: `src/app/wizard-demo/page.tsx`

Update the existing `acceptButtons` render prop to disable the submit button when `summary` contains errors:

```tsx
acceptButtons={(summary) => {
  const hasErrors = summary && Object.keys(summary.error ?? {}).length > 0
  return (
    <Button
      variant="default"
      disabled={!!hasErrors}
      onClick={() => toast.success('Formularz wysłany!')}
    >
      Wyślij formularz
    </Button>
  )
}}
```

**UI impact**: Submit button is disabled when validation errors exist on the summary page.
