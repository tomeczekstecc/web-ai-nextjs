# Implementation Plan: Top-Nav Layout Mode

**Branch**: `015-top-nav-layout` | **Date**: 2026-05-20 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/015-top-nav-layout/spec.md`

## Summary

Complete the deferred `top-menu` layout mode. When `NEXT_PUBLIC_NAV_LAYOUT=top-menu`, the app renders a sticky horizontal navigation bar using shadcn/ui `NavigationMenu` instead of the collapsible sidebar. A new `AppShell` Server Component owns the layout switch, the session fetch, and `SidebarProvider` — replacing the boilerplate currently duplicated in every authenticated page. Both `dashboard` and `applications` pages are refactored to use `AppShell`. One-line fix to `NavUser` removes its `SidebarProvider` dependency. No new API contracts or data models are introduced.

## Design Decisions (from grilling session)

| # | Decision |
|---|---|
| Shell | `AppShell` wrapper component — single global wrapper for all authenticated pages |
| AppShell type | Server Component — calls `getNavLayout()` + `requireAuthorizedAppSession(returnTo)` |
| Page title | `AppShell` takes `title` prop — sidebar: `SiteHeader`; top-nav: static slim sub-header below the bar |
| NavUser fix | Swap `useSidebar().isMobile` → `useIsMobile()` — one-line, no new component |
| Mobile | Hamburger + `Sheet` from left |
| Top-nav item display | Text only — no icons |
| Flyout sub-items | Text only — plain links |
| Brand | `"eNGO"` as `<Link href="/dashboard">` |
| Auth returnTo | Explicit prop on `AppShell`, defaults to `"/"` |
| File placement | Flat in `src/components/` |
| Sidebar width | Standardised to `72` spacing units in `AppShell` — eliminates `72` vs `76` drift |
| Mobile Sheet content | Collapsible sections — reuses `Collapsible` + `NavMain` pattern |
| Top bar stickiness | `sticky top-0 z-50` |
| Title sub-header | Static — scrolls with page content |

## Component Architecture

### `AppShell` (Server Component)

```
AppShell (RSC)
  ├── requireAuthorizedAppSession(returnTo)  → user data
  ├── getNavLayout()                          → "sidebar" | "top-menu"
  │
  ├── if "sidebar":
  │     SidebarProvider (--sidebar-width: 72, --header-height: 12)
  │       AppSidebar [user, variant="inset"]
  │       SidebarInset
  │         SiteHeader [title]
  │         children
  │
  └── if "top-menu":
        div.flex.min-h-svh.flex-col
          AppTopNav [user]              ← sticky top bar
          div.border-b (title strip)    ← static sub-header
            h1 [title]
          main.flex-1                   ← page content
            children
```

### `AppTopNav` (Client Component)

```
AppTopNav
  ├── useMenuConfig()              → MenuConfig | loading | error
  ├── filterFeatures(features)     → visibleFeatures
  ├── filterSettings(settings)     → visibleSettings
  │
  ├── header.sticky.top-0.z-50.border-b
  │     ├── Brand: Link href="/dashboard" → "eNGO"
  │     │
  │     ├── Desktop (md+): NavMainTop [items=visibleFeatures]
  │     │     NavigationMenu
  │     │       per FeatureItem:
  │     │         has submenu → Trigger + Content (text-only sub-links)
  │     │         direct link → NavigationMenuLink + navigationMenuTriggerStyle()
  │     │
  │     ├── Desktop (md+): NavUser [user, settings=visibleSettings]
  │     │
  │     └── Mobile (<md):
  │           Sheet
  │             SheetTrigger: hamburger Button
  │             SheetContent (left)
  │               NavMain [items=visibleFeatures]   ← reused collapsible nav
  │               NavUser [user, settings=visibleSettings]
  │
  └── Loading state: skeleton items instead of NavMainTop
```

## UI Impact

### Light / Dark theme
`NavigationMenu` primitives inherit shadcn/ui CSS variable tokens (`--background`, `--foreground`, `--muted`, `--accent`) — theme parity is automatic.

### Responsiveness
- `md` breakpoint (768 px): desktop `NavigationMenu` is `hidden md:flex`; hamburger + Sheet is `flex md:hidden`
- Top bar height matches `--header-height` CSS variable (`calc(var(--spacing) * 12)` = 48 px) for visual consistency with sidebar mode

### Polish UI
All labels come from `MenuConfig.features[].label` and `MenuConfig.settings[].label` — already in Polish from the MSW fixture and future backend. Brand text `"eNGO"` is unchanged.
