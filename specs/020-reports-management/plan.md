# Implementation Plan: Reports Management Module

**Branch**: `020-reports-management` | **Date**: 2026-05-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/020-reports-management/spec.md`

---

## Summary

Build a full Reports Management module: a paginated searchable table at `/(app)/reports/` with Generate, Edit, Delete row actions; a shared three-step wizard (Dane podstawowe, Zapytanie, Uprawnienia) for create/edit/view; a Monaco SQL editor that follows app theme; a dual-list permissions transfer widget; async report generation with Zustand-persisted polling state; and a parameters drawer using `FormRepeater` for runtime values. All new UI reuses existing `Wizard`, `Sheet`, `DataTable`, `Dialog`, and `FormRepeater` primitives with minimal net-new abstraction.

## Implementation Design

### UI Impact

- New route group at `/(app)/reports/` with list + 3 wizard pages
- Reports list: paginated `DataTable` with name (link), status (Badge), actions (3 icon buttons)
- Wizard: 3 steps in existing `WizardShell` layout (vertical stepper sidebar, progress bar, sticky footer)
- Step 1: standard form inputs + `TextareaWiz` with `maxLength=2000`
- Step 2: dynamically imported Monaco editor + custom `ParameterTable` + test query button + result preview
- Step 3: `DualListTransfer` with two panels + 4 transfer buttons + search per panel
- Generation drawer: `Sheet` (right side) with `FormRepeater` listing runtime param inputs
- Delete confirmation: `Dialog` with destructive confirm button naming the report

### Light / Dark Theme Impact

- Monaco editor reads `resolvedTheme` from `next-themes` — no additional work after wiring
- `DualListTransfer` uses Tailwind semantic tokens (`bg-muted`, `border`, `text-foreground`) — inherits theme automatically
- All new components use existing shadcn/ui primitives which are already theme-aware

### Responsiveness Impact

- Reports list: existing `DataTable` is responsive; actions column uses `icon-sm` buttons
- Wizard: existing `WizardShell` handles responsive layout (vertical stepper hidden on mobile, horizontal stepper shown)
- `DualListTransfer`: stacks vertically on mobile (flex-col), side-by-side on md+ (flex-row)
- Generation drawer: `Sheet` with `side="right"` — full-width on mobile, `max-w-md` on desktop

### Laravel Integration Impact

- All endpoint shapes documented in `contracts/backend.md`
- Next.js API route handlers under `src/app/api/reports/` act as the integration seam
- Frontend mapper (`mapper.ts`) converts snake_case payload to camelCase model
- No backend implementation required to start frontend work (mock data in route handlers)

### Simplicity Assessment

- Reuses 6 existing primitives: `Wizard`, `Sheet`, `DataTable`, `Dialog`, `FormRepeater`, `TableRepeater` (no, not `TableRepeater` — custom `ParameterTable` for step 2)
- One new package: `@monaco-editor/react`
- One new UI primitive: `DualListTransfer`
- 5 surgical edits to existing files
- ~25 new files — appropriate for a full CRUD module with wizard + async generation

### Duplication / Complexity Risk

- `ParameterTable` (wizard step 2) vs `FormRepeater` (generation drawer): different contexts justify different approaches — no duplication
- `DualListTransfer` is self-contained; no risk of leaking permissions logic into unrelated features

## Success Criteria Mapping

| Criterion | Implementation |
|-----------|---------------|
| SC-001: table loads < 2 s | `prefetchQuery` in page server component + `HydrationBoundary`; `staleTime: 30_000` |
| SC-002: wizard step transition < 300 ms | Existing `WizardShell` `nav()` — pure Zustand state update, no network call (saveOnPageChange: false) |
| SC-003: test query ≤ 30 s | No frontend timeout below 30 s; show spinner during fetch |
| SC-004: generation polling visible feedback | Zustand `generationStates` drives per-row spinner; polls every 3 s |
| SC-005: destructive actions behind confirmation | Delete behind `Dialog`; wizard cancel navigates without `Dialog` (no data yet saved) |
| SC-006: Monaco theme switch < 500 ms | React state update via `useTheme()` — instant re-render |
| SC-007: CRUD toast < 300 ms of server response | `onSuccess`/`onError` callbacks in mutation hooks call `toast.*` synchronously |
| SC-008: dual-list reflects selections immediately | Local `Set<number>` state — no async |
| SC-009: drawer opens < 200 ms | Sheet open is CSS transition; `setGeneratingReport` is synchronous |
| SC-010: drawer inline validation | TanStack Form field validators; `form.handleSubmit` blocks on error |
