# Implementation Plan: Wizard System — Phase 1 Foundation

**Branch**: `006-wizard-foundation` | **Date**: 2026-05-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/006-wizard-foundation/spec.md`

## Summary

Build the foundational layer of the reusable wizard engine: a global Zustand store (wizard slice, Redux DevTools middleware), a `WizardProvider` context that manages navigation and form state, a `useWizard()` hook for page components, and a `<Wizard>` shell with a vertical side nav and Back/Next navigation buttons. No data fetching, validation, or field components are in scope — only the navigable multi-page shell with persistent form state.

## Technical Context

**Language/Version**: TypeScript 5.8

**Testing**: N/A — constitution forbids automated tests

**Scale/Scope**: 8 new files, 1 updated demo page, 0 existing files modified outside wizard scope

## Complexity Tracking

| Decision | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Zustand global store | Wizard state must survive component unmounts and be accessible across wizard tree without prop drilling | React `useReducer` + lifting state would require prop drilling to every page component |
| devtools middleware | Developer experience — Redux DevTools shows wizard state changes in real time | Without it debugging form state is opaque |
| Separate WizardContext.ts from WizardProvider.tsx | Avoids circular imports (useWizard hook imports context, provider imports hook) | Single file causes circular dependency |
